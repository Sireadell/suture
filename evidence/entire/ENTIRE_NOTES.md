# Entire gaps and findings

Entire CLI 0.11.4, Windows 11, Claude Code, 2026-10-10. Each item has exact steps to repeat it.

| # | What went wrong or is unclear | Steps to repeat | Effect on Suture |
| --- | --- | --- | --- |
| 1 | The "Link this commit to session context?" prompt cannot be answered when an agent runs `git commit`, so the commit gets no checkpoint | In a repo with Entire enabled, let a Claude Code session run `git commit` itself after editing files | We set `{"commit_linking":"always"}` in `.entire/settings.local.json` (local file, not committed). The docs do describe this setting, but only as a convenience, not as the thing an agent-driven workflow needs. A "using Entire with an agent that commits" note would help |
| 2 | Checkpoints are only created for sessions run inside the repo folder | Run Claude Code from another folder (every early Suture session ran from `hackathons\orion-agents`), edit files in the repo, commit. `entire checkpoint list` shows 0 | The Clerk file was written before any checkpoint could exist. See WHERE_THE_BUG_CAME_FROM.md |
| 3 | A manual attach leaves a checkpoint ID in the session state that points at nothing | `.git/entire-sessions/fef4abba-ced1-4858-aca2-bdb3f1d8d5a8.json` has `"attached_manually": true`, `"checkpoint_count": 0`, `"last_checkpoint_id": "01M4JN47KTJYS3FCWM29CD5MD7"`. Then `entire checkpoint explain 01M4JN47KTJYS3FCWM29CD5MD7` prints `no checkpoint or commit found matching` and `git for-each-ref refs/entire` shows only the other checkpoint. `entire session list` still prints that ID next to the session | `entire session list` shows a checkpoint that cannot be opened. Anyone reading the list would think the Clerk-writing session has one |
| 4 | `entire plugin install graph` succeeds but the program cannot run on this PC | `entire plugin install graph` then `entire graph version`. Output: `fork/exec ...\entire\plugins\bin\entire-graph.exe: An Application Control policy has blocked this file.` The file is 75 MB and not code-signed (`Get-AuthenticodeSignature` says NotSigned). Windows Smart App Control is on (`HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy` shows `VerifiedAndReputablePolicyState = 1`) | Graph and Brain (Brain needs Graph for code, and ships as the same kind of unsigned binary) could not be run here. The install step reports success even though the tool is unusable. Plugin binaries on Windows would need signing, or the docs should say Smart App Control blocks them. We did not work around the block, it is a Windows security setting |
| 5 | `entire activity` and `entire recap` need a login, with a different message each | Not logged in: `entire activity` prints "Not logged in. Run 'entire login' to authenticate." and `entire recap` prints "Run `entire login` to re-authenticate." (it says re-authenticate though there was never a login) | Login needs a person to approve a code in a browser, so an agent cannot do it alone |
| 6 | `entire dispatch` wrote a one-line summary of the whole repo and called a note-taking commit a "build system update" | Run `entire dispatch` after login | It only saw the one checkpointed commit. Fine for a demo, but it is not an account of the Suture work |
| 7 | `entire experts targets/clerk` says "No agent provenance found" | Run it on any path whose commits have no checkpoint | Expected, but it has no hint that unlinked commits are the reason |
| 8 | `entire repo list` fails without `--project` | `entire repo list` prints `required flag(s) "project" not set` | The docs list `repo` without saying a repo mirrored from GitHub needs a project name to list. We confirmed the import through the website instead |
| 9 | `entire search` returns raw JSON with no human view | `entire search "Clerk order fallback"` | Fine for agents, hard to read for the founder |
| 10 | `entire import` would create checkpoints for a past session, but it copies the whole transcript | `entire import claude-code --path <old project folder> --session fef4abba-... --dry-run` reports "Would import 314 turn(s)". That transcript holds unrelated work and a pasted API key. Checkpoints in a public repo are public | We did not import it. A way to import only a slice of turns, or a redaction preview, would make this safe to use on a long session |
| 11 | Trails need a feature flag turned on by an Entire person | The hackathon page says to fill an access form, then turn on Runners, Auto build on push and Trails in the repo's entire.io settings, then `entire runner setup -y` | Not done. Needs the founder to file the form. Repo is public so settings are on the founder's account |
| 12 | Early Suture commits in the public history carry a `Co-Authored-By` line and a "Checkpoint:" bookkeeping commit exists on the checkpoint ref | `git log --all --format=%B` | Not an Entire fault. Noted so the founder knows what a reviewer will see |

## Unclear in the docs

| Topic | What is unclear |
| --- | --- |
| Checkpoint IDs | The docs show 26-character IDs in two spots and 12-character hex IDs in others. With CLI 0.11.4 new ones are 26-character (ours: 26). The hackathon page does not say which to submit, so submit the 26-character one |
| `entire status` | Prints "tracking diverged from current HEAD after git history movement" for an idle session after new commits. Neither the docs nor the message say whether it matters |
| Link | The hackathon page gives only the commit URL. There is no direct per-checkpoint URL in the docs, so the commit URL plus the ID is the right pair |
