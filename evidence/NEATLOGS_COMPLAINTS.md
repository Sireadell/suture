# neatlogs gaps and bugs found while building Suture

Each item says what we tried, what happened, and what we expected. Dates are 2026-10-10 unless noted. Project: Sire's project.

| # | Area | What happened | How to reproduce | What we expected |
|---|------|---------------|------------------|------------------|
| a | MCP | `triage_list` returns 0 fixes while the dashboard Incidents page shows the Clerk incident (f7b8c3b3, Investigated) | Call MCP `triage_list` with any status, then open app.neatlogs.com Incidents | Same incident in both places |
| b | CLI docs | Docs target neatlogs-cli 0.2.1 and describe an incidents command. npm latest is 0.2.0 and has no incidents command | `npm i -g neatlogs-cli`, `neatlogs --help`, compare with docs.neatlogs.com/cli | Docs match the published version |
| c | Fixes | Docs say Claude Code workers are planned. The Fix in menu shows "Open in Claude Code" (a hand-off, no PR) and "Cloud Agent > Claude Code" is labelled Coming soon. Only Cursor has a cloud agent | Incident page, Fix in dropdown | Either a working worker that opens a PR, or the menu says hand-off |
| c2 | Fixes | When the Claude Code deep link cannot open, the page says "prompt copied instead", but the system clipboard still held the old value. The prompt can only be read by hooking `navigator.clipboard.writeText` | Click Fix in > Claude Code with no handler registered, then paste | Prompt on the clipboard, or a visible copy box |
| c3 | Fixes | The hand-off prompt describes the incident only (unknown order ids). A separate Investigate chat finding (malformed JSON answered 200) does not reach the fix prompt unless you raise a new incident | Compare the chat answer "Clerk Malformed Request Bug" with the Fix prompt | Chat findings attachable to the incident or fix |
| d | CLI auth | CLI login is read only (`project:read`). `alerts create` returns FORBIDDEN, so no verdict write-back and no alert creation from the terminal | `neatlogs auth status`, then `neatlogs alerts create --body-stdin` | A way to log in with write scopes |
| d2 | CLI/API | `neatlogs evaluators run` returns `NOT_FOUND_OR_OPERATION_DISABLED` (gate `tier-c-compute`), although the docs list it | `echo '{"traceId":"..."}' \| neatlogs evaluators run <id> --request-stdin` | Run works, or docs mark it unavailable |
| e | Cost | Cost reads 0 for the Clerk traces and leaves out thinking tokens. Our own counter saw 26,135 thinking tokens on one call, neatlogs reported 2,624 total tokens | Trace 10fe7420b391694cbc43bfac26f30f32 vs `own_counters_crosscheck` in evidence/scorecard.json | Thinking tokens counted and priced |
| f | GitHub app | Callback returned a redirect_uri error when connecting GitHub | Settings > Integrations > GitHub | Fixed by neatlogs, now works |
| g | Dashboard | Detections page shows "Couldn't load detections" although `GET /api/v1/detections` returns 200 with 4 detections and the CLI lists them. The page stays empty after Retry | Open Detections tab | List of 4 detections |
| g2 | Alerts | New alert wizard says "Create a detection first" and the detection dropdown is disabled, so no alert can be created, although the "Clerk wrong answer" detection exists and is active | Alerts > Alerts > New alert > Threshold or Per event > Condition step | Detection dropdown lists "Clerk wrong answer" |
| g3 | Chats | Asked the chat assistant to create an alert rule. It said it has no tool for alert rules and quoted a wrong host and path (`api.neatlogs.com/api/v1/public/alert_rules`, the docs say `app.neatlogs.com/api/v1/public/alert-rules`) | Chat: "Create an alert rule on detection X" | Either create it or quote the real path |
| h | Plugin | Claude Code plugin traces arrive one per tool call (names like `Read`, `mcp__claude-in-chrome__navigate`, `AGENT`), not one trace per session as docs say. They stay `finalizationStatus: pending` with 0 spans | `neatlogs traces list --workflow claude-code` after a session | One session trace with a span tree |
| h2 | Plugin | A workflow named after a pasted system reminder text appears in the workflow picker (`<system-reminder> Linked...`) | Evals > New eval > Conditions > Workflow picker | Stable workflow name such as claude-code |
| i | Evals | Trace-level eval with the AI evaluator never scored traces that were still `finalizationStatus: pending`. The 17 newest Clerk traces had no assignment and the eval stayed at 67 percent (35 of 52 items) for over 15 minutes with no error message | Create eval over Clerk workflow within minutes of sending traffic | A visible "waiting for finalization" or a retry |
| i2 | Evals | Conditions only offer ranges of 7 days and up, and Trace ID matches one id only. A small hand-picked set of traces cannot be evaluated | Evals > New eval > Conditions | A trace picker or list of ids |
| i3 | Traces | Spans stay at 0 and status `pending` for several minutes after `neatlogs.flush()` and `shutdown()` | Send 3 requests through a script that calls flush and shutdown, list traces | Spans visible after flush |
| j | UI | The dashboard tab froze twice (screenshots time out, "page still loading") on the Evals page while an eval was running | Open Evals page with an eval in progress | Page responds |
