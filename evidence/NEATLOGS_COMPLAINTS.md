# neatlogs gaps and bugs found while building Suture

Each item says what we tried, what happened, and what we expected. Dates are 2026-10-10 unless noted. Project: Sire's project.

| # | Area | What happened | How to reproduce | What we expected |
|---|------|---------------|------------------|------------------|

| n | Incidents API | No read operation for incidents or their fixes. With neatlogs-cli 0.2.1 (published, `neatlogs --version` prints 0.2.1) `neatlogs schema search incident` returns only `POST /api/v1/public/incidents/external` (publish a snapshot), and `schema search triage` and `schema search fix` return nothing. `neatlogs incidents` has only `publish`. The CLI login has only project:read. We were told incidents are readable on the API and CLI. Question for neatlogs: which operation lists or gets an incident and its fix (for incident f7b8c3b3-c933-441a-85d2-9e2f6c8be8bd), and what scope does the token need? | `neatlogs schema search incident`, `neatlogs incidents --help` | A GET list and GET by id for incidents and fixes, with the scope named in the docs |
